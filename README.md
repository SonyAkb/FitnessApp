# 🏋️ FitQuest — фитнес-приложение с игровым персонажем

> Веб-приложение (с возможностью упаковки в мобильное), в котором пользователь планирует тренировки, отслеживает прогресс, тестово оплачивает подписку и «прокачивает» виртуального питомца, выполняя реальные тренировки.

---

## 📌 Идея проекта

FitQuest — это фитнес-трекер с элементами геймификации:

- пользователь создаёт расписание тренировок и планы (программы);
- выполняет тренировки в приложении (таймер, чек-лист упражнений, история);
- получает уведомления-напоминания;
- видит прогресс на дашбордах;
- оформляет тестовую платную подписку (тестовый режим платёжной системы);
- «ухаживает» за виртуальным персонажем — тот растёт/радуется, если пользователь достигает целей тренировок, и «грустит»/деградирует при пропусках;
- получает простые ИИ-рекомендации (лёгкая модель, обучена на Google Colab);
- может «подключить умные часы» — на деле это эмулятор, генерирующий синтетические данные (шаги, пульс).

## 🧱 Архитектура и стек

### Почему веб, а не нативное мобильное приложение

- **Frontend:** React + TypeScript (Vite) — SPA;
- при необходимости «мобильного приложения» — оборачиваем готовый веб-фронт в **Capacitor** (или делаем **PWA** — «Добавить на экран»).
- Тестировать можно прямо в браузере — просто открыв адрес локального/задеплоенного сервера.

### Backend

- **Python (FastAPI)** — основной бэкенд, модульный монолит: у каждого модуля свой роутер/сервис/модели, чтобы не было конфликтов в общем коде.
- Альтернатива для отдельных сервисов — **C# (.NET Minimal API)**, если кому-то удобнее (например, можно вынести один модуль отдельным сервисом на C#, чтобы потренироваться со связкой двух языков через REST). Для учебных целей это даже плюс — команда потренируется в межсервисном взаимодействии.
- **База данных:** PostgreSQL + SQLAlchemy / EF Core.
- **Инфраструктура:** Docker Compose (frontend + backend + db одним `docker-compose up`), чтобы у всех поднималось одинаково независимо от ОС.

### Прочие технические решения

| Часть | Технология | Комментарий |
|---|---|---|
| Платежи | Тестовый режим Stripe **или** ЮKassa/CloudPayments (sandbox) | Не боевые ключи, только тестовые карты |
| ИИ-модуль | Небольшая модель (scikit-learn / простая сеть), обучение в Google Colab, экспорт весов в backend, либо инференс-эндпоинт через ngrok | Специально «слабый» ИИ — рекомендательная логика, не тяжёлые модели |
| Умные часы | Эмулятор-сервис, генерирующий шаги/пульс/сон по расписанию или случайно | Реальные часы не нужны |
| Уведомления | Web Push (Service Worker) + email через тестовый SMTP (Ethereal/Mailtrap) | Без реальной рассылки |
| Аутентификация | JWT | Стандартная схема |

## 🧩 Модули (распределение на 5 человек)

Каждый модуль = зона ответственности одного человека (backend-роуты + связанные frontend-страницы + свои таблицы БД). Модуль 6 — самый лёгкий, собран из нескольких небольших частей.

### Модуль 1 — Пользователи, Аутентификация и Расписание
- Регистрация/вход, роли (пользователь/админ), профиль (цели, вес, уровень).
- Календарь/расписание тренировок (создание, перенос, повторяющиеся события).
- Сущности: `User`, `ScheduleEvent`.
- Эндпоинты: `/auth/*`, `/profile`, `/schedule`.

### Модуль 2 — Планы тренировок и Тренировочный модуль
- Создание программ тренировок (набор упражнений, подходы/повторы/вес).
- Экран «выполнения» тренировки: таймер отдыха, чек-лист, фиксация факта выполнения.
- История тренировок пользователя.
- Сущности: `WorkoutPlan`, `Exercise`, `WorkoutSession`.

### Модуль 3 — Игровой персонаж (геймификация)
- Виртуальный питомец/персонаж, у которого есть параметры (энергия, настроение, уровень).
- Начисление «очков ухода» за выполненные тренировки/цели, деградация при пропусках.
- Достижения/квесты («тренируйся 3 дня подряд» и т.п.).
- Сущности: `Companion`, `Achievement`.

### Модуль 4 — Платежи и подписки
- Тарифы (free/pro), оформление подписки через **тестовый** режим платёжной системы.
- Обработка вебхуков (успех/провал оплаты, sandbox), история платежей.
- Ограничение доступа к фичам по тарифу (например, ИИ-рекомендации только на pro).
- Сущности: `Subscription`, `Payment`.

### Модуль 5 — Дашборды и Уведомления
- Экран аналитики: прогресс по весам/повторениям, календарь активности, графики.
- Система уведомлений: напоминания о тренировке, поздравления, «питомец грустит» и т.п.
- Сущности: `NotificationRule`, агрегирующие вью/запросы для графиков (без новых таблиц — данные модулей 1–3).

### Модуль 6 — ИИ-рекомендации, эмуляция часов и документация
- Небольшая ML-модель (обучается в Google Colab): например, рекомендация следующей тренировки/нагрузки на основе истории пользователя.
- Сервис-эмулятор «умных часов»: генерирует и отдаёт синтетические данные активности (шаги, пульс) через API/вебсокет.
- Ведение технической документации проекта (архитектура, README отдельных модулей, инструкция по запуску, API-спецификация — например Swagger из FastAPI).

> Модуль 6 сознательно собран из трёх небольших частей — это ок, если по объёму он получается меньше остальных.

## 🔗 Как модули стыкуются

- Общая база данных (PostgreSQL), у каждого модуля — свои таблицы, но есть общие связи (все ссылаются на `User`).
- Один репозиторий, бэкенд как модульный монолит: `backend/modules/<module_name>/`.
- Frontend — общий SPA, каждый модуль — свой раздел роутинга: `frontend/src/pages/<module_name>/`.
- Взаимодействие модулей через события/сервисный слой (например: завершение тренировки в Модуле 2 → событие → Модуль 3 обновляет питомца, Модуль 5 создаёт уведомление).

## 🗺️ Примерный план разработки (roadmap)

1. **Неделя 1** — договориться о контрактах API (OpenAPI-схема), поднять skeleton backend/frontend, Docker Compose, настроить БД и миграции.
2. **Неделя 2–3** — каждый разрабатывает свой модуль (CRUD + базовый UI), еженедельная интеграция в общую ветку.
3. **Неделя 4** — связка модулей между собой (события завершения тренировки → питомец → уведомления → дашборд).
4. **Неделя 5** — тестовые интеграции: платежи (sandbox), ИИ-эндпоинт из Colab, эмулятор часов.
5. **Неделя 6** — полировка UI, упаковка в PWA/Capacitor для демонстрации на телефонах, финальное тестирование, документация.
