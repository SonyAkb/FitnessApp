# 📋 План разработки FitQuest

## 0. Что уже сделано в каркасе (можно проверить прямо сейчас)

- Backend (FastAPI) поднимается, создаёт таблицы, все 6 модулей подключены и **реально протестированы**:
  регистрация → логин → создание плана тренировки → старт/завершение сессии →
  автоматическое обновление персонажа → дашборд → расписание → эмулятор часов → AI-рекомендация.
- Frontend (React+TS) собирается без ошибок (`npm run build`), все 6 разделов открываются,
  ходят в реальные эндпоинты бэкенда, есть логин/регистрация с JWT.
- Docker Compose поднимает всё одной командой на любой ОС (Mac/Windows).
- Stripe-интеграция закодирована по-настоящему (Checkout Session + webhook), но чтобы кнопка
  сработала, нужно вписать свои тестовые ключи в `.env` (см. `docs/PLAN.md` → раздел Модуля 4).

Дальше — зона ответственности каждого разработчика: доработать "TODO" внутри своего модуля.

## 2. Как взять модуль в работу

1. Создать ветку: `feature/module-<номер>-<имя>`, например `feature/module-2-training`.
2. Прочитать TODO-комментарии в файлах своего модуля — это готовый чек-лист.
3. Модель данных менять можно свободно на старте проекта (пока не накопилось данных) —
   таблицы создаются автоматически при старте (`Base.metadata.create_all`, см. `backend/app/main.py`).
4. Задокументировать новые эндпоинты — они и так попадают в Swagger автоматически:
   **http://localhost:8000/docs** (это и есть API-документация, отдельно писать не нужно).
5. Проверить свой модуль вручную через Swagger UI ИЛИ через фронт (`http://localhost:5173`).
6. Сделать PR, попросить одного человека из команды посмотреть (даже поверхностно).

### Definition of Done для модуля (минимум для MVP)
- [ ] Эндпоинты отвечают ожидаемые данные (проверено вручную в Swagger или через фронт)
- [ ] Нет `raise Exception` без обработки — ошибки должны возвращать понятный HTTP-статус
- [ ] Убраны/выполнены TODO, критичные для демонстрации
- [ ] Страница на фронте открывается без белого экрана и ошибок в консоли браузера

## 4. Модуль 4 (Платежи) — как получить тестовые ключи Stripe

1. Зарегистрироваться на https://dashboard.stripe.com (можно тестовым email, реальные платежи не нужны).
2. В левом меню включить **Test mode** (переключатель обычно уже включён по умолчанию).
3. **Developers → API keys** — скопировать `Secret key` (`sk_test_...`) → в `.env` как `STRIPE_SECRET_KEY`.
4. **Product catalog → создать продукт** ("FitQuest Pro"), добавить цену (например, $9.99/месяц) →
   скопировать `price_...` id → в `.env` как `STRIPE_PRICE_ID_PRO`.
5. Для локального теста вебхука установить [Stripe CLI](https://stripe.com/docs/stripe-cli) и выполнить:
   ```bash
   stripe listen --forward-to localhost:8000/payments/webhook
   ```
   Команда выведет `whsec_...` — вставить в `.env` как `STRIPE_WEBHOOK_SECRET`.
6. Тестовая карта для оплаты: `4242 4242 4242 4242`, любая будущая дата, любой CVC.

Без этих ключей всё остальное приложение работает нормально — просто кнопка
"Оформить Pro" на фронте вернёт понятную ошибку вместо перехода на Stripe.

## 5. Модуль 6 (AI) — как подключить модель из Google Colab

Сейчас `backend/app/modules/ai_watch/ai_recommender.py` — простое правило (if/else),
чтобы MVP работал без реальной модели с первого дня. План апгрейда:

1. Обучить лёгкую модель в Google Colab (`ai/` — папка для ноутбука/данных).
   Идея для старта: классификатор "нужен лёгкий/тяжёлый день" на основе
   количества тренировок за последние 7 дней + самочувствия (если будет такое поле).
2. Экспортировать модель (`pickle`/`joblib`), скачать файл из Colab.
3. Положить файл в `backend/app/modules/ai_watch/model/` (создать папку).
4. В `ai_recommender.py` заменить `rule_based_recommend` на загрузку модели и `model.predict(...)`.
5. Если модель тяжелее и не хочется тащить её в основной backend-образ — альтернативный вариант:
   держать инференс прямо в Colab-ноутбуке с `ngrok`, и дергать этот URL через `httpx` из бэкенда
   (более "учебный" вариант, показывает работу с внешним AI-сервисом).

## 6. Технические соглашения

- **Ветки:** `feature/module-<N>-<name>`, мерж в `main` через Pull Request.
- **Стиль кода backend:** обычный PEP8, без строгого линтера на старте (не тратим время).
- **Стиль кода frontend:** компоненты — `PascalCase.tsx`, вызовы API — только через `src/api/client.ts`.
- **Секреты:** никогда не коммитить `.env` (уже в `.gitignore`), только `.env.example`.
- **Миграции БД:** на этапе MVP — `Base.metadata.create_all()` при старте (см. `main.py`).
  Если после недели 3 схема стабилизируется и понадобится не терять данные при изменениях —
  переходим на Alembic (`pip install alembic`, `alembic init alembic`, дальше — по документации).
- **Порты по умолчанию:** backend `:8000`, frontend `:5173`, Postgres `:5432`.
